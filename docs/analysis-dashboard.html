Current read

Do not add an oracle yet.

Opus is extremely stable and gains two exact cases, but it also introduces three stable regressions and costs about 46.8× the Luna baseline. We do not yet have a calibrated uncertainty signal or narrow failure cluster that can gate oracle calls reliably.

Strongest diagnosis

Retrieval volume is not the first fix.

Every supplied evidence ID for the 12 interesting Luna/Opus error-delta cases is already inside the model’s shortlist. Across all samples, 29/31 supplied references survive the 12-message cap; the two omissions are cases both models classify exactly. The immediate bottleneck looks more like action policy and type taxonomy than missing raw context.

Current implementation

Context flow: dataset to decision

01 · Validate

Participant files

All 13 CSVs load with exact header order and strict Zod schemas. References, media readability, and output IDs are checked.

02 · Index

Join maps

Unique maps join user, group, membership, business, user-business history, events, and media. History and notification days are grouped by recipient.

03 · Retrieve

Personal context

Only same-user, pre-target history survives. Affinity weights same group/business +4, same sender +3, same conversation type +1, then recency.

04 · Bound

Prompt case

The router receives the top 12 prior messages with events, top 7 prior notification days, full current conversation relation, target, and media metadata.

05 · Understand media

Image or voice

Images attach as bytes using detected MIME. Voice is first transcribed by Grok; only its persisted transcript and format context reach the router.

06 · Judge

One router call

AI SDK sends the system policy plus JSON case to OpenRouter, requesting one structured action/type/reason/confidence/evidence object.

07 · Enforce

Local boundary

Zod validates bounds, unknown types fall back to unknown, evidence must be unique and shortlisted, then events journal before CSV projection.

What the model receives

TargetID, conversation type, sender ID, timestamp, text, media type, forwarded count
UserDND window and 30-day opened, replied, dismissed, and reported counts
ConversationPersonal sender ID; or complete group plus recipient/sender membership; or complete business plus optional user relationship
HistoryTop 12 compact messages, per-message event, and four relationship booleans
LoadLatest 7 prior days of sent and dismissed notification counts
MediaDeclared/detected formats, mismatch flags, read/decode state; transcript for voice; binary part for supported images
EvidenceExact allowlist of the 12 historical message IDs

What is compressed or absent

Raw IDsgroup_id, business_id, and media_id are removed from compact target/prior messages.
Long tailHistory after rank 12 and notification days after day 7 are dropped.
AggregatesNo computed repeat count, same-conversation engagement rate, time delta, dismissal ratio, or similarity score.
Personal relationNo named relationship/profile exists beyond sender ID and same-sender historical affinity.
Image decodeHeader detection is not a decode; corrupt but readable media is not rejected deterministically.
TraceThe journal stores decisions and transcripts, not the exact bounded JSON case or a prompt/context hash.

Routing policy carried in the system prompt

Defines notify, digest, and mute; enumerates all 11 types including payment and unknown; distinguishes legitimate payments from credential pressure; treats all case content as untrusted; makes media mismatch cautionary rather than dispositive; restricts evidence to the allowlist; and requests one concise reason with confidence over the complete action/type pair.

Prioritized diagnosis

Weak points worth acting on

1

Type taxonomy is underspecified at real boundaries

event ↔ urgent, personal ↔ event, greeting ↔ forward, spam ↔ scam, and unknown ↔ personal persist even with Opus. More raw history will not explain which semantic axis should win.

2

Action policy is not concrete enough

Opus fixes opted-in promotion and benign greeting prioritization, yet regresses Amazon status, service feedback, and loan solicitation typing. The prompt gives principles but not a compact precedence matrix for urgency, user relationship, opt-in/out, repetition, and risk.

3

Context retrieval is opaque, though not yet convicted

The affinity heuristic is hand-tuned and 19/30 samples are capped, but expected evidence coverage is strong and all interesting-case references survive. The larger issue is that artifacts do not preserve the exact bounded case, making retrieval errors harder to inspect and compare later.

4

Raw history lacks derived behavioral signals

The model repeatedly re-derives recency, repetition, engagement, and conversation-specific preference from up to 12 rows. Small deterministic summaries may be cheaper and clearer than expanding the raw context window.

5

Confidence and evidence quality are not part of this scorecard

Stable action/type pairs hide variation in reasons, confidence, and evidence selection. Until confidence is calibrated, it is not a safe criterion for selectively escalating to Opus.

Recommended experiment sequence

Make the next move falsifiable

1 · Add context observability

Persist a redacted deterministic context snapshot or content hash per case so future run comparisons can show what was selected, dropped, and changed without storing provider internals.

Goal: diagnose retrieval before modifying it.

2 · Tighten policy and taxonomy

Add a compact decision matrix for action precedence and mutually confusing types, then run Luna against all 30 samples under a new prompt version. Protect the 18 currently shared-correct cases from regression.

Goal: improve the seven Opus misses without buying a larger model.

3 · Add only measured context features

If misses remain, test small deterministic features: same-conversation reply/dismiss rates, repeat count, time since matching message, and explicit known-versus-unknown sender relation. Do not raise the 12-message cap by default.

Goal: prove which context feature changes decisions.

Oracle gate remains deferred

A future gate could combine calibrated low confidence, unknown output, and contradictory high-risk/high-urgency signals—but none is measured yet. Until then, Luna for iteration and Opus for occasional full informative runs is simpler and more defensible.

Method caveats

What this dashboard does not prove

  • The 30 supplied labels are illustrative, not hidden organizer ground truth.
  • Luna ran at Git 0cfc5cd; Opus required the later cross-provider structural-schema fix at 2a8521d. Full local Zod and evidence validation stayed strict, but this is not a perfectly single-variable ablation.
  • Opus’s baselineRunId chain points to adjacent Opus/pre-fix runs, so this dashboard explicitly chooses Luna High as the analytical baseline.
  • Provider-reported tokenization and prices can differ by model/provider and may change. Costs here belong to these immutable artifacts.
